# Bracket Drawing Migration Plan

## Scope

Dokumen ini merencanakan migrasi flow drawing bagan dari project CI3 `htdocs/dps` ke project CI4 `htdocs/dps-ci4`, khusus untuk:

- Drawing bagan tanding.
- Drawing bagan battle seni.
- Manual shuffle.
- Shuffle dengan formula lama.
- Full random + Persilat standard.
- Renderer visual bagan dari JSON lama.
- Sinkronisasi bagan dan update hasil pertandingan ke JSON.

Manual bracket lanjutan dan statistik dikerjakan setelah parity drawing + renderer tercapai.

## Goals

- CI4 menghasilkan format JSON bracket yang kompatibel dengan sistem lama.
- CI4 bisa menampilkan bagan tanding dan battle seni dengan renderer visual, bukan raw JSON.
- CI4 mendukung tiga mode drawing lama: manual, formula, dan full random Persilat.
- CI4 menyimpan data `pertandingan`, `battle_seni`, dan `penampilan_seni` konsisten dalam transaksi database.
- Flow lama tetap bisa dipakai untuk update pemenang, progression bracket, dan statistik berikutnya.

## Non-Goals

- Mengganti library bracket pada tahap awal.
- Membuat UI manual bracket baru yang berbeda total dari CI3.
- Membuat statistik sebelum generator dan renderer bracket stabil.
- Rewrite ke React/Vue/SPA.

## Required JSON Compatibility

CI4 must produce JSON compatible with `jquery.bracket` and CI3 behavior:

```json
{
  "teams": [
    [
      {
        "id_pendaftar": 1,
        "id_peserta_tanding": 10,
        "id_kontingen": 5,
        "nama_pendaftar": "Nama Atlet",
        "nama_kontingen": "Nama Kontingen",
        "negara": "Indonesia",
        "url_bendera": "..."
      },
      null
    ]
  ],
  "results": [
    [
      [[null, null, " Match 1 (Semi Final)"]],
      [[null, null, " Match 3 (Final)"]]
    ]
  ]
}
```

Important compatibility notes:

- `teams[x][0]` maps to blue corner in legacy DB flow.
- `teams[x][1]` maps to red corner in legacy DB flow.
- `results[0][round][match]` is required by `jquery.bracket` and legacy update logic.
- Battle seni uses `id_kelompok_peserta_seni` and `anggota_kelompok_peserta_seni` instead of tanding fields.
- `skipConsolationRound` must follow `juara_tiga_bersama`.

## Migration Phases

### Phase 1: Port Core Generator Parity

Target: `app/Services/SistemGugurTunggalService.php`

Tasks:

- Port `_hitung_pertandingan()` as `hitungPertandinganAwal()`.
- Port `_get_babak()` as `getBabak()`.
- Port `_create_array_peserta()` as `createArrayPeserta()`.
- Port `_create_template_bracket()` as `createTemplateBracket()`.
- Port `_create_template_dari_standar_persilat()` as `createTemplateDariStandarPersilat()`.
- Port `_transform_template_team()` as `transformTemplateTeam()`.
- Port `_isi_template_bracket_tanding()` as `isiTemplateBracketTanding()`.
- Port `_isi_template_bracket_battle()` as `isiTemplateBracketBattle()`.
- Port `get_template_bracket()` as `getTemplateBagan()`.
- Ensure generated `teams` and `results` match CI3 structure.

Acceptance criteria:

- Tanding JSON generated by CI4 has non-empty `teams` and full `results` rounds.
- Battle JSON generated by CI4 has non-empty `teams` and full `results` rounds.
- For participant count 2, 3, 4, 5, 8, 16, output shape matches CI3.
- For participant count <= 20 with Persilat mode, `template_persilat.json` is used.
- For participant count > 20, fallback formula template is used.

### Phase 2: Implement Drawing Modes

Target: `app/Services/SistemGugurTunggalService.php`

Tasks:

- Replace current minimal `acakBaganTanding()` with mode-aware logic.
- Replace current minimal `acakBaganBattleSeni()` with mode-aware logic.
- Add enum-like mode strings or bool-compatible arguments:
  - `formula`
  - `full_random_persilat`
  - `manual`
- Tanding formula mode:
  - Query peserta ordered by `kontingen.nama_kontingen`.
  - Use formula template, not Persilat standard.
- Tanding full random Persilat mode:
  - Recreate legacy `_get_peserta_tanding_match_fixing()` behavior.
  - Respect `peserta_tanding.nomor_bagan` when present.
  - Fill empty slots with remaining peserta.
  - Use Persilat standard template when eligible.
- Battle formula mode:
  - Query kelompok ordered by `kontingen.nama_kontingen`.
  - Use formula template.
- Battle full random Persilat mode:
  - Query kelompok random.
  - Use Persilat standard template when eligible.
- Use DB transactions for every drawing operation.
- Reject redraw if any match/battle is already linked to schedule detail.

Acceptance criteria:

- Formula mode produces deterministic spread by kontingen order.
- Full random mode changes participant order and uses Persilat slot layout for <= 20 participants.
- Redraw is blocked when `detail_jadwal_tanding` or `detail_jadwal_seni` rows exist.
- DB writes for bracket JSON and match/battle rows commit or rollback together.

### Phase 3: Persist Match And Battle Rows Correctly

Targets:

- `app/Services/SistemGugurTunggalService.php`
- `app/Models/PertandinganModel.php`
- `app/Models/BattleSeniModel.php`
- `app/Models/PenampilanSeniModel.php`

Tasks:

- Insert `pertandingan` rows from generated `data_pertandingan`.
- Insert `battle_seni` rows from generated `data_battle_seni`.
- For tanding, include `id_atlet_merah`, `id_atlet_biru`, `id_pemenang`, `jenis_kemenangan`, `nomor_pertandingan_selanjutnya`, and `babak`.
- For battle, create `penampilan_seni` rows for merah/biru like CI3.
- For battle, map `id_kelompok_peserta_seni_pemenang` to the correct `id_penampilan_seni_pemenang`/CI4 field equivalent.
- Review schema differences between CI3 and CI4 field names before implementation.

Acceptance criteria:

- First round match rows match bracket `teams` slot mapping.
- BYE rows have `jenis_kemenangan = BYE` and winner set.
- Later round rows have null participants until progression.
- Battle creates penampilan rows consistently and does not duplicate stale records after redraw.

## Data Safety Rules

- Never redraw if match/battle is already scheduled.
- Never delete unrelated participant or payment data.
- Delete and recreate only rows owned by the selected competition/pool.
- Wrap bracket JSON update and row recreation in one transaction.
- If any insert/update fails, rollback all changes.
- Preserve user/manual `nomor_bagan` when using full random Persilat tanding mode.

## Risks

- CI4 schema field names may differ from CI3, especially battle winner fields.
- Existing CI4 `PertandinganModel` and `BattleSeniModel` allowed fields may need updates.
- Old bracket plugin depends on jQuery load order.
- If generated JSON differs from legacy `jquery.bracket` schema, renderer may silently fail.
- Battle seni progression creates new `penampilan_seni` rows per round in CI3; this must be matched carefully.

## Recommended Implementation Order

1. Copy `template_persilat.json` into CI4 public assets.
2. Replace minimal generator with CI3-compatible generator functions.
3. Implement formula and full random mode for tanding.
4. Implement formula and full random mode for battle seni.
5. Fix tanding renderer to use legacy-compatible JSON only.
6. Add battle seni visual renderer.
7. Add manual shuffle pages and submit handlers.
8. Port update result and progression methods.
9. Port sync methods.
10. Start manual bracket refinements and statistics.
